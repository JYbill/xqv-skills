# Jev curl 调用

仅用 curl 访问官方 HTTP API；认证直接读取当前执行进程的 `TYPESAFE_API_KEY`，无需 SDK、MCP 或独立配置文件。

## 适用场景与不适用场景

- 适合材料充分、判断标准明确的语义任务：分类与分流、从已有候选中选择、判断内容是否符合要求，以及按给定等级评分。能写成选择题，不代表适合交给 Jev。
- 能通过确定的条件、计算或数据库查询得到结果时，优先使用代码或查询，不额外调用模型。
- 需要资料检索、多步推理或方案设计时，先完成这些工作，再将其中材料和标准已明确的局部判断交给 Jev；不把完整的复杂决策简化成一次选择。
- 候选可能不覆盖实际情况时，增加“以上皆非”或“信息不足”选项，并明确各自含义。不要在证据不足时强制选出业务选项。
- 将结果接入自动执行前，用实际任务样本验证判断效果和错误后果，确定哪些结果可执行、哪些需要补充信息或人工复核；不单凭模型置信度决定自动执行。

## 执行

1. 区分生成命令与实际调用：仅要求示例时输出命令；要求执行时，检查 curl 可用且环境变量非空，只报告是否存在，不打印密钥。缺少密钥时请用户在执行环境中配置；不搜索其他凭据文件。桌面 Agent 的执行进程未必继承终端里新设置的变量。
2. 首次构造请求时读取 [HTTP 请求与返回](references/http.md)。需要新增参数、核对接口变更或排查字段错误时，再读取其中链接的官方 API 文档；不加载 SDK 或无关案例。
3. 将待判断内容放入 `state`，问题放入 `instructions`，候选或等级放入 `criteria`。选项用 `choice`，是否成立用 `noul`，程度评分用 `score`。问题 ID 只用于匹配返回结果，不承担提示词含义。
4. 相同状态下互不依赖的问题可放入同一次请求；问题之间不能引用尚未返回的答案。外部请求仅包含任务所需且已授权发送给 TypeSafe 的内容。
5. 用 JSON 文件或带引号的 heredoc 传递请求体，通过 curl 执行。密钥只进入认证头，不写入请求体、日志或仓库；执行时关闭 shell 跟踪，避免 `curl -v` 或 trace 输出认证头。
6. 同时检查 curl 退出码、HTTP 状态及 `answers` 中每个问题的类型和结果。调用失败不能报告为模型判断成功。选中某个操作不代表已执行该操作。

## 返回与失败

- 报告实际模型、问题结果和必要的概率；有需要时附 `usage`。没有真实调用时明确标注请求示例。
- `choice` 必须落在提交的候选内；`noul` 是“是”的概率，不是布尔值；`score` 按返回的 `legend` 解读，不擅自当成百分制。
- `confidence` 不等于事实正确率；业务阈值由任务确定，不统一套用固定阈值。
- 401/403 停止并报告认证或权限问题；422 修正明确的字段错误再调用。429/529 按服务端等待提示或指数退避最多重试两次；超时或连接中断说明结果未知，重试可能重复计费。
