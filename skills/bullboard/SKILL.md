# Bull Board

使用原生 curl 调用面板已有 API，不增加包装脚本，不直接连接 Redis。执行前读取 [HTTP API 参考](references/http-api.md) 的认证与查询部分；写操作或等待任务时，再读取对应部分。

## 环境与目标

- 地址、用户名、原始密码分别读取 `BULL_URL`、`BULL_USER`、`BULL_PASSWORD`。不回退到其他服务的凭据或服务端密码哈希。
- `BULL_URL` 表示面板挂载根地址，可包含路径前缀；去除末尾 `/` 后拼接 `/api/...`。不在 skill 中保存实际地址、账号或密码。
- 用户显式配置优先。变量缺失时检查项目是否已通过 mise 配置；若有，使用 `mise exec -C <项目根目录> -- <命令>` 加载，不输出完整配置或环境。仍缺失时报告缺少的变量，不自动写配置。
- 更换地址时核对对应凭据，不将原站点凭据自动发送给其他主机。HTTP Basic 仅用于已确认的可信网络；其他网络使用 HTTPS。

## 执行流程

1. 准备临时认证配置，以最小只读请求验证 HTTP 状态和 JSON 结构。认证成功只证明凭据被接受，不声称已核对账号角色。
2. 目标未知时读取一次队列列表；使用响应中的完整 `name` 定位队列，不按相似名称或树状显示名称猜测。已知准确队列名和任务 ID 时直接读取任务详情。
3. 按用户目标查询或执行已授权操作。写入前核对目标、当前状态、`readOnlyMode` 及相关能力；批量重试、清理或清空必须有对应范围的授权，单任务授权不扩展为整个队列。已有明确授权不重复询问。
4. 报告目标面板、队列、任务 ID、HTTP 状态及必要证据。任务数据、结果和错误可能含敏感内容，只输出完成请求所需的脱敏摘要。

## 请求与等待边界

- 连接超时默认 10 秒、单请求总超时 60 秒。客户端超时不保证服务端查询已停止，不能靠反复重试解决慢查询。
- 列表默认每页 20 条，按状态和页码取数，不自动扫描全部历史任务。`/api/queues` 仍可能统计所有可见队列，`activeQueue` 只限定任务列表；跟踪已知任务优先用详情接口。
- 普通查询取得所需数据即结束。日志按需读取，优先服务端支持的范围参数；没有分页能力时不得虚构参数，也不反复拉取全量日志。
- 重试、添加或提前执行请求返回后，默认报告接口结果即结束，不查询后续执行状态、不跟随日志。接口成功不等于任务执行完成。
- 暂停、恢复和删除等状态变更可回读一次验证效果；未能证实时只报告请求结果，不扩大为持续等待。暂停队列不等于终止正在执行的任务。
- 仅当用户明确要求等待时轮询。用户时限优先，否则每 10 秒一次、总计最多 30 分钟，开始时说明上限；单次等待不超过 60 秒并定期反馈。到期仅结束本地等待，不取消任务。
- 写请求超时、断连或结果不明时不自动重发。只读请求遇到 429、5xx 可按 `Retry-After` 或短暂退避最多重试两次；长退避不在默认查询中阻塞等待，报告稍后再查。

## 能力与结果边界

接口与字段以目标部署版本为准，不能把上游最新路由当作当前服务已支持的能力。已有只读验证不等于所有写操作已经实测；未验证的写能力通过部署对应源码、路由和权限核对，不用真实写入探测。

进度由 Worker 上报，结果和日志取决于业务记录；`progress=0` 不代表未执行，空日志不代表没有错误。用任务详情的 `status` 判断状态，不仅看 `failedReason` 或 `isFailed`，它们可能保留历史失败信息。已清理任务不能通过面板恢复历史结果，404 也不能直接当作成功或删除完成。
