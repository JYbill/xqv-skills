# Jenkins

使用 `curl` 调用 Jenkins Remote Access API，不下载或使用 `jenkins-cli.jar`，不增加包装脚本。

## 操作范围

- 连接、身份、任务、构建、日志和制品查询属于只读操作。
- 触发或重跑构建、修改配置、停止或删除构建等写操作，须在用户明确授权的动作和目标范围内执行。已有明确授权不重复索要确认。
- 涉及本项目流水线时先读 [Git 管理说明](../../../docs/开发指南/git管理.md)，实际任务配置和插件能力需现场核对，不把历史记录当成当前配置。

## 执行流程

执行请求前读取 [Remote Access API 参考](references/remote-access-api.md) 的环境、认证和只读检查部分，再按任务读取查询、触发、等待或配置修改部分。

1. 确定控制器和预期用户。地址统一读取当前环境变量 `JENKINS_URL`；所需变量缺失时报告变量名，不自动加载或写入项目配置。
2. 选择凭据并准备临时 curl 配置，再通过 `/whoAmI/api/json` 验证身份。`/login` 和 `X-Jenkins` 仅作为辅助诊断。
3. 从 API 返回的 URL 定位目标，逐级读取 Folder；确认任务类型及参数，不按相似名称猜测。
4. 按授权执行操作。密码认证的写请求复用获取 crumb 时的 cookie；文件放入系统临时目录，每次操作独立创建并在结束时清理，不跨任务持久化。
5. 输出控制器、目标任务、HTTP 状态和必要的构建号、结果、Revision 或日志证据。凭据、cookie、crumb、敏感参数不得输出。

## 触发、停止与删除

- 默认触发只发送请求。HTTP 201/202 表示请求已被接受，不代表构建已开始或成功；有 `Location` 时提供队列地址。
- 默认不查询队列、不等待构建、不跟随日志。用户本次请求已包含等待或日志跟随时，按参考文档执行，无需另行确认。
- 完整重跑、Declarative Pipeline 阶段重启和 Replay 是不同操作；先根据用户意图及目标构建实际 action 选择接口，不把 Replay 当作通用重跑。
- 普通“停止构建”只执行标准 `/stop`。`/term`、`/kill` 和删除构建的破坏性更高，必须分别符合参考文档中的前置条件和授权要求，不自动升级。
- POST 响应不明确或连接中断时不自动重试，避免重复触发。
- 目标 API 不可访问、身份不符、缺少所需权限，或无法唯一对应目标时，停止依赖该信息的操作，报告已确认的证据及缺失信息。
